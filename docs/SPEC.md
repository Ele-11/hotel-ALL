# 易宿酒店预订平台 MVP 需求规格

## 1. MVP 目标

本项目 MVP 只实现酒店预订平台的最小业务闭环：

商户录入酒店和房型
↓
管理员审核并发布酒店
↓
用户查询已发布酒店
↓
用户查看酒店详情和房型
↓
用户创建基础预订记录

MVP 不追求完整 OTA 平台能力，只验证用户端、商户端、管理员端的核心流程可用。

---

## 2. 必须实现的功能

- 用户端酒店查询
- 用户端酒店列表
- 用户端酒店详情
- 用户创建基础预订记录
- 商户注册和登录
- 商户录入、编辑自己的酒店信息
- 商户维护自己酒店的房型和价格
- 管理员登录
- 管理员审核、驳回、发布、下线酒店
- 基础角色权限控制

---

## 3. 用户端功能

### 3.1 酒店查询页

- 支持按城市或地点查询酒店
- 支持按关键字查询酒店
- 支持选择入住日期和离店日期
- 点击查询后进入酒店列表页

### 3.2 酒店列表页

- 只展示已发布酒店
- 展示当前查询条件
- 展示酒店列表
- 支持分页或加载更多
- 点击酒店进入详情页

列表项必须展示：

- 酒店名称
- 酒店地址
- 酒店星级
- 酒店最低价格
- 酒店图片或默认占位图

### 3.3 酒店详情页

- 展示酒店名称
- 展示酒店图片或默认占位图
- 展示酒店星级、地址、设施
- 展示入住日期、离店日期和间夜数
- 展示房型和价格
- 房型按价格从低到高排序
- 用户选择房型后可以创建基础预订记录

### 3.4 预订功能

- 登录用户可以创建预订记录
- 预订记录关联用户、酒店、房型、入住日期、离店日期、入住人数和总价
- MVP 只创建预订记录，不接入支付

---

## 4. 管理端功能

### 4.1 登录和注册

- 商户可以注册和登录
- 管理员可以登录
- 登录后根据角色进入对应页面
- 管理员账号建议通过系统预置，不开放普通注册创建管理员

### 4.2 商户酒店管理

- 商户可以创建酒店
- 商户可以编辑自己创建的酒店
- 商户可以维护自己酒店的房型和价格
- 商户提交或保存酒店后，酒店进入待审核状态
- 商户可以查看酒店审核状态
- 审核不通过时，商户可以查看驳回原因

酒店必填字段：

- 酒店中文名
- 酒店英文名
- 酒店地址
- 酒店星级
- 酒店开业时间
- 房型名称
- 房型价格

酒店可选字段：

- 酒店图片
- 酒店设施

### 4.3 管理员酒店审核

- 管理员可以查看待审核酒店
- 管理员可以审核通过酒店
- 管理员可以驳回酒店，并填写驳回原因
- 管理员可以发布审核通过的酒店
- 管理员可以下线已发布酒店
- 下线不是删除数据，下线酒店可以恢复发布

---

## 5. 角色权限

| 角色 | 权限 |
|---|---|
| 游客 | 可以查询酒店、查看酒店列表、查看酒店详情；不能创建预订 |
| 普通用户 | 可以查询酒店、查看酒店详情、创建自己的预订记录 |
| 商户 | 可以创建和编辑自己名下的酒店、房型和价格；可以查看自己酒店的审核状态和驳回原因 |
| 管理员 | 可以审核、驳回、发布、下线和恢复发布酒店 |

权限规则：

- 用户端只展示已发布酒店
- 普通用户只能创建自己的预订记录
- 商户只能管理自己创建的酒店和房型
- 管理员接口必须校验管理员权限
- 管理员不直接编辑商户提交的酒店内容

---

## 6. 酒店状态

| 状态 | 说明 |
|---|---|
| 待审核 | 商户提交后等待管理员审核 |
| 审核不通过 | 管理员驳回酒店，需要记录驳回原因 |
| 审核通过 | 酒店信息已通过审核，但尚未发布 |
| 已发布 | 用户端可以查询和查看 |
| 已下线 | 用户端不可见，数据保留，可以恢复发布 |

- 真实支付
- 真实地图服务
- 真实定位服务
- 复杂推荐算法
- 酒店供应商对接
- 复杂优惠券系统
- 房态库存锁定
- 订单取消、退款和支付状态流转
- 用户评价
- 用户收藏
- 分享功能
- 多图上传和文件存储服务
- 热门景点、周边交通、周边商场、优惠信息的完整管理
- 复杂快捷标签筛选

---

## 8. MVP 验收标准

- 商户可以创建酒店和房型，并提交审核
- 管理员可以审核通过并发布酒店
- 已发布酒店可以出现在用户端列表中
- 用户可以查看酒店详情和房型价格
- 登录用户可以选择房型并创建基础预订记录
- 下线酒店不会出现在用户端
- 不同角色只能访问自己有权限的功能
