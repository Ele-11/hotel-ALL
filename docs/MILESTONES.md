# 易宿酒店预订平台 MVP 开发里程碑

本文档根据 `docs/SPEC.md` 拆分 MVP 开发阶段。每个阶段只完成一个核心目标，避免引入非 MVP 功能。

MVP 主线：

商户录入酒店和房型
↓
管理员审核并发布酒店
↓
用户查询已发布酒店
↓
用户查看酒店详情和房型
↓
用户创建基础预订记录

---

## Milestone 1：项目基础结构

核心目标：

搭建前后端和数据库开发基础，让项目可以启动和连接。

任务：

- 初始化 Monorepo 和 pnpm workspace
- 创建用户端前端应用
- 创建后端 API 应用
- 配置 TypeScript
- 配置 Tailwind CSS
- 配置 Prisma 和 PostgreSQL 连接
- 配置基础启动脚本

验收标准：

- 前端应用可以启动
- 后端 API 可以启动
- 后端可以连接 PostgreSQL
- 项目目录结构清晰，能支撑后续 MVP 开发

---

## Milestone 2：核心数据模型

核心目标：

建立 MVP 所需的数据结构。

任务：

- 创建用户模型，支持 USER、MERCHANT、ADMIN 三种角色
- 创建酒店模型，支持酒店基础信息和状态
- 创建房型模型，支持房型名称和价格
- 创建预订模型，记录用户、酒店、房型、日期、人数和总价
- 创建审核记录或审核字段，记录审核状态和驳回原因
- 添加基础 seed 数据，包括管理员账号和测试数据

验收标准：

- 数据库迁移成功
- 数据库包含管理员账号
- 酒店状态覆盖待审核、审核不通过、审核通过、已发布、已下线
- 酒店、房型、用户、预订之间的关系清晰

---

## Milestone 3：登录注册和角色权限

核心目标：

完成基础账号体系和角色访问控制。

任务：

- 实现商户注册和登录
- 实现普通用户注册和登录
- 实现管理员登录
- 登录后返回当前用户身份
- 根据 USER、MERCHANT、ADMIN 控制接口访问权限
- 限制管理员账号通过系统预置，不开放普通注册创建管理员

验收标准：

- 普通用户可以登录并访问用户功能
- 商户可以登录并访问商户功能
- 管理员可以登录并访问管理员功能
- 普通用户不能访问商户和管理员接口
- 商户不能访问管理员接口
- 未登录用户不能创建预订

---

## Milestone 4：商户酒店管理

核心目标：

让商户可以录入和维护自己的酒店与房型。

任务：

- 实现商户创建酒店
- 实现商户编辑自己创建的酒店
- 实现商户维护自己酒店的房型和价格
- 保存或提交酒店后进入待审核状态
- 商户可以查看自己酒店的审核状态
- 审核不通过时，商户可以查看驳回原因

验收标准：

- 商户可以创建包含必填字段的酒店
- 商户可以为自己的酒店创建房型和价格
- 商户只能编辑自己创建的酒店和房型
- 新建或编辑后的酒店不会直接出现在用户端
- 酒店提交后状态为待审核

---

## Milestone 5：管理员审核发布

核心目标：

让管理员控制酒店是否可以在用户端展示。

任务：

- 实现管理员查看待审核酒店
- 实现审核通过
- 实现审核不通过，并填写驳回原因
- 实现发布审核通过的酒店
- 实现下线已发布酒店
- 实现下线酒店恢复发布

验收标准：

- 管理员可以审核商户提交的酒店
- 审核不通过时必须保存驳回原因
- 审核通过但未发布的酒店不会出现在用户端
- 已发布酒店可以出现在用户端
- 已下线酒店不会出现在用户端
- 下线不会删除酒店数据

---

## Milestone 6：用户端酒店查询和详情

核心目标：

让用户可以找到并查看已发布酒店。

任务：

- 实现酒店查询页，支持城市或地点、关键字、入住日期、离店日期
- 实现酒店列表页，只展示已发布酒店
- 酒店列表展示名称、地址、星级、最低价格、图片或默认占位图
- 酒店列表支持分页或加载更多
- 点击酒店进入详情页
- 酒店详情展示酒店信息、日期、间夜数、房型和价格
- 房型按价格从低到高排序

验收标准：

- 用户只能查询到已发布酒店
- 查询条件可以传递到列表页
- 酒店列表可以进入对应详情页
- 酒店详情展示房型和价格
- 已下线酒店不会出现在列表或详情中

---

## Milestone 7：基础预订记录

核心目标：

让登录用户可以基于酒店房型创建预订记录。

任务：

- 用户在酒店详情页选择房型
- 用户填写或确认入住人数
- 根据入住日期、离店日期和房型价格计算总价
- 创建基础预订记录
- 预订记录关联用户、酒店、房型、入住日期、离店日期、入住人数和总价

验收标准：

- 未登录用户不能创建预订
- 登录用户可以创建自己的预订记录
- 预订记录保存的酒店、房型、日期、人数和总价正确
- 预订流程不接入真实支付
- 不实现取消、退款和支付状态流转

---

## Milestone 8：MVP 闭环验收

核心目标：

验证 MVP 主线完整可用。

任务：

- 验证商户创建酒店和房型
- 验证管理员审核通过并发布酒店
- 验证用户可以查询已发布酒店
- 验证用户可以查看酒店详情和房型
- 验证用户可以创建基础预订记录
- 验证下线酒店不会出现在用户端
- 验证不同角色只能访问自己有权限的功能

验收标准：

- 商户录入酒店和房型的流程可用
- 管理员审核、发布、下线流程可用
- 用户查询、详情、预订流程可用
- 角色权限控制符合 `docs/SPEC.md`
- 暂不实现功能没有进入 MVP 范围
